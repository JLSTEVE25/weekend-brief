# Spec: Replace Password Gate with Passkey (Face ID / Touch ID) Auth

## What This Is

Replace the hardcoded "stevenson" password in the Weekend Brief with WebAuthn passkey authentication. Users (John and Sara) will log in with Face ID on iPhone or Touch ID on Mac — one tap, no password to type or remember.

## Why

1. **Learning project** — understand how passkeys/WebAuthn work. Reusable pattern for future projects.
2. **Better security** — current password is visible in HTML source code. Passkeys use public-key cryptography tied to the user's biometrics.
3. **Better UX** — glance at phone or tap fingerprint sensor instead of typing a password every time.

## Architecture Overview

```
Current flow:
  User → GitHub Pages (index.html) → type "stevenson" → see brief

New flow:
  User → GitHub Pages (index.html) → tap "Sign in" → Face ID / Touch ID prompt
    ↕ (behind the scenes)
  Cloudflare Worker handles the WebAuthn challenge/response
    ↕
  Cloudflare KV stores registered passkeys + session tokens
```

Three components:
1. **Cloudflare Worker** — serverless function (free tier) that handles passkey registration and login
2. **Cloudflare KV** — key-value store (free tier) that persists registered credentials and sessions
3. **Frontend changes** — replace the password gate JS in the generated HTML with WebAuthn API calls

## Component 1: Cloudflare Worker

Create a Cloudflare Worker at a URL like `https://weekend-brief-auth.{your-subdomain}.workers.dev`

The Worker needs 4 endpoints:

### `POST /register/begin`
- Called when a new user wants to register their passkey
- Generates a WebAuthn registration challenge
- Returns the challenge + options to the browser
- **Guard this:** Only allow registration when there are fewer than 2 registered credentials (John + Sara). After 2 registrations, this endpoint should return 403. Alternatively, require a one-time registration code stored in a KV key (e.g., `registration_secret`) that must be passed in the request body.

### `POST /register/complete`
- Receives the signed registration response from the browser
- Verifies it and stores the credential public key in KV
- KV key format: `credential:{credentialId}` → `{ publicKey, userId, userName, createdAt }`

### `POST /login/begin`
- Generates a WebAuthn authentication challenge
- Stores the challenge temporarily in KV with a 5-minute TTL
- Returns challenge + allowCredentials list (all registered credential IDs)

### `POST /login/complete`
- Receives the signed authentication response
- Verifies the signature against the stored public key
- On success, generates a session token (random 32-byte hex string)
- Stores session in KV: `session:{token}` → `{ userId, createdAt, expiresAt }` with 30-day TTL
- Returns the session token as an HttpOnly cookie OR in the response body

### `GET /verify`
- Checks if the current session token (from cookie or Authorization header) is valid
- Returns `{ authenticated: true, user: "John" }` or `{ authenticated: false }`

### Dependencies

Use the `@simplewebauthn/server` npm package in the Worker. It handles all the WebAuthn crypto. Install it as part of the Worker's `package.json`. Key functions:
- `generateRegistrationOptions()`
- `verifyRegistrationResponse()`
- `generateAuthenticationOptions()`
- `verifyAuthenticationResponse()`

### CORS

The Worker must set CORS headers allowing requests from the GitHub Pages origin:
```
Access-Control-Allow-Origin: https://jlsteve25.github.io
Access-Control-Allow-Methods: POST, GET, OPTIONS
Access-Control-Allow-Headers: Content-Type
Access-Control-Allow-Credentials: true
```

### Worker Configuration

These values are needed in the Worker's environment (set via `wrangler.toml` or Cloudflare dashboard):
- `RP_ID`: `jlsteve25.github.io` (the relying party — must match the domain the user sees)
- `RP_NAME`: `Weekend Brief`
- `RP_ORIGIN`: `https://jlsteve25.github.io`
- `REGISTRATION_SECRET`: a one-time code John sets to protect the registration endpoint

### 2b. Inject the auth JavaScript

In `generate_brief.py`, there's already a pattern where feedback JS gets injected after Claude returns the HTML. Add a similar injection for auth JS. Insert this before `</body>`:

```javascript
<script>
const AUTH_API = 'https://weekend-brief-auth.YOUR_SUBDOMAIN.workers.dev';

async function checkSession() {
  try {
    const resp = await fetch(`${AUTH_API}/verify`, { credentials: 'include' });
    const data = await resp.json();
    if (data.authenticated) {
      document.getElementById('auth-gate').style.display = 'none';
      document.getElementById('main-content').style.display = 'block';
    }
  } catch (e) {
    console.log('Session check failed, showing login');
  }
}

async function handlePasskeyLogin() {
  try {
    // Step 1: Get challenge from server
    const beginResp = await fetch(`${AUTH_API}/login/begin`, {
      method: 'POST',
      credentials: 'include'
    });
    const options = await beginResp.json();

    // Step 2: Browser prompts Face ID / Touch ID
    // Convert base64url strings to ArrayBuffers for the WebAuthn API
    options.challenge = base64urlToBuffer(options.challenge);
    options.allowCredentials = options.allowCredentials.map(cred => ({
      ...cred,
      id: base64urlToBuffer(cred.id)
    }));

    const credential = await navigator.credentials.get({ publicKey: options });

    // Step 3: Send signed response to server
    const completeResp = await fetch(`${AUTH_API}/login/complete`, {
      method: 'POST',
      credentials: 'include',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        id: credential.id,
        rawId: bufferToBase64url(credential.rawId),
        response: {
          authenticatorData: bufferToBase64url(credential.response.authenticatorData),
          clientDataJSON: bufferToBase64url(credential.response.clientDataJSON),
          signature: bufferToBase64url(credential.response.signature)
        },
        type: credential.type
      })
    });

    const result = await completeResp.json();
    if (result.authenticated) {
      document.getElementById('auth-gate').style.display = 'none';
      document.getElementById('main-content').style.display = 'block';
    } else {
      alert('Authentication failed. Try again.');
    }
  } catch (e) {
    console.error('Passkey login error:', e);
    alert('Passkey login failed. Make sure you have a registered passkey.');
  }
}

// Base64url <-> ArrayBuffer helpers
function base64urlToBuffer(base64url) {
  const base64 = base64url.replace(/-/g, '+').replace(/_/g, '/');
  const pad = base64.length % 4 === 0 ? '' : '='.repeat(4 - (base64.length % 4));
  const binary = atob(base64 + pad);
  return Uint8Array.from(binary, c => c.charCodeAt(0)).buffer;
}

function bufferToBase64url(buffer) {
  const bytes = new Uint8Array(buffer);
  let binary = '';
  bytes.forEach(b => binary += String.fromCharCode(b));
  return btoa(binary).replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');
}

// Check session on page load
checkSession();
</script>
```

## Component 3: Cloudflare Setup (manual steps for John)

Claude Code can create all the code, but John will need to do these steps manually in the Cloudflare dashboard:

1. **Create a Cloudflare account** (free) at cloudflare.com if you don't have one
2. **Install Wrangler CLI:** `npm install -g wrangler` (Claude Code can do this)
3. **Login:** `wrangler login` (opens browser, John clicks authorize)
4. **Create KV namespace:** `wrangler kv:namespace create "PASSKEY_STORE"` (Claude Code can run this)
5. **Set the registration secret:** `wrangler kv:key put --binding=PASSKEY_STORE "registration_secret" "YOUR_CHOSEN_CODE"` 
6. **Deploy the Worker:** `wrangler deploy` (Claude Code can run this)
7. **Note the Worker URL** — paste it into `generate_brief.py` as the `AUTH_API` value
8. **Add Worker URL as a GitHub Secret** — `PASSKEY_AUTH_URL` so generate_brief.py can inject it dynamically

## Fallback

If WebAuthn isn't supported (very old browser), show a message: "Your browser doesn't support passkey login. Please use Safari, Chrome, or Edge on a modern device." Do NOT fall back to the old password — that defeats the purpose.

## Edge Cases

- **Lost phone / new device:** John would need to re-register. Keep `register.html` in the repo but require the registration secret. To re-register, bump the credential limit or delete old credentials from KV manually via `wrangler kv:key delete`.
- **Session expiry:** After 30 days, the session token expires. User just taps Face ID again — no disruption, just one extra auth.
- **Cloudflare Worker down:** The brief HTML still loads (it's on GitHub Pages), but auth fails. User sees the login screen with no way in. This is unlikely — Workers have 99.99% uptime — but worth knowing.
